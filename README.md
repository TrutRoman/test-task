# Тестове завдання: Telegram-бот, сайт з авторизацією, Unity-гра і 3D-модель

| Папка | Що всередині |
|---|---|
| [`bot/`](bot) | Telegram-бот для зв'язку клієнта з оператором (TypeScript, grammY, long polling) |
| [`web/`](web) | Сайт з реєстрацією, входом, кабінетом і адмін-панеллю (TypeScript, Express 5, EJS, SQLite) |
| [`unity/`](unity) | Гра «Тестік гейм»: персонаж від третьої особи, меню паузи, збереження (Unity 6, URP) |
| [`model/`](model) | Low-poly стілець: Python-скрипт для Blender, `chair.blend` і `chair.fbx` |

## Вимоги

- Бот і сайт: **Node.js 24** або новіший. Node сам запускає `.ts`-файли (type stripping), тому збірка не потрібна. `tsc` використовується лише для перевірки типів. npm входить до складу Node.js.
- Гра: **Unity 6000.6.2f1** через Unity Hub. Для збірки `.exe` потрібен модуль Windows Build Support (Mono), він входить у Windows-версію редактора.
- Модель: **Blender 5.2**.

Проєкти незалежні. У бота й сайту свій `package.json`, свій `.env` і своє `npm install`.

## 1. Telegram-бот

### Як отримати токен у @BotFather

1. Відкрийте в Telegram [@BotFather](https://t.me/BotFather) і надішліть команду `/newbot`.
2. Вкажіть **ім'я** бота (відображається в контактах, може бути будь-яким).
3. Вкажіть **username**: 5–32 символи, латиниця, цифри та `_`, обов'язково має закінчуватися на `bot` (наприклад, `my_support_bot`).
4. BotFather надішле токен вигляду `110201543:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw`. Тримайте його в секреті, як пароль. Якщо токен «засвітився», згенеруйте новий командою `/token` у BotFather.

### Як дізнатися свій Telegram ID (для оператора)

Найпростіше — написати будь-що боту [@userinfobot](https://t.me/userinfobot) (сторонній бот), він відповість вашим числовим ID.

Без сторонніх ботів: напишіть щось своєму боту, поки він **не запущений**, і відкрийте в браузері
`https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`. У відповіді ваш ID — це поле `message.from.id`.

### Налаштування `.env`

```bash
cd bot
cp .env.example .env
```

| Змінна | Опис |
|---|---|
| `BOT_TOKEN` | Токен від @BotFather |
| `OPERATOR_ID` | Числовий Telegram ID оператора |
| `DB_PATH` | Шлях до файлу SQLite, наприклад `bot.db` (створюється автоматично) |
| `LOG_PATH` | Файл журналу бота, наприклад `logs/bot.log` (папка створюється автоматично) |

Якщо `.env` або будь-якої змінної немає, чи `OPERATOR_ID` не є числом, бот одразу падає з описом помилки.

### Запуск

```bash
cd bot
npm install
npm start
```

Перевірка типів: `npm run typecheck`.

### Як користуватися

1. **Оператор** один раз надсилає боту `/start`. Без цього Telegram не дозволить боту писати оператору першим. Після `/start` у оператора з'являється клавіатура: «📊 Статистика», «👥 Останні клієнти», «🚫 Заблоковані».
2. **Клієнт** (інший акаунт) надсилає `/start` і отримує вітальне повідомлення (що це тестовий бот підтримки і як ним користуватися) та кнопку «/start» внизу чату. Далі пише боту: текст, фото, файл, голосове тощо.
3. Бот пересилає повідомлення оператору і відповідає на нього службовим повідомленням «👤 Ім'я (@username), ID …» з кнопкою «🚫 Заблокувати». Telegram не дозволяє додати кнопку до пересланого повідомлення (`forwardMessage` не має параметра `reply_markup`), тому кнопка в окремому повідомленні.
4. **Оператор** відповідає через **reply** на переслане повідомлення (не на службове). Відповідь (будь-якого типу) отримує саме той клієнт, який написав.
5. Заблокований клієнт отримує відповідь, що його повідомлення не доставляються, а оператору нічого не надходить. Розблокувати можна в «🚫 Заблоковані».

Дані зберігаються в SQLite: таблиця `clients` (id, username, first_name, banned, created_at) і `messages` (id, client_id, created_at), де `messages.id` — `message_id` пересланого повідомлення в чаті оператора. Тому reply на старі повідомлення працює й після перезапуску бота.

Кнопки оператора обробляються лише для `OPERATOR_ID`: якщо клієнт надішле текст «📊 Статистика», це буде звичайне повідомлення оператору.

## 2. Сайт

### Налаштування `.env`

```bash
cd web
cp .env.example .env
```

| Змінна | Опис |
|---|---|
| `PORT` | Порт сервера, наприклад `3000` |
| `SESSION_SECRET` | Секрет для підпису cookie сесії, мінімум 32 символи |
| `DB_PATH` | Шлях до файлу SQLite, наприклад `data.db` (створюється автоматично) |
| `LOG_PATH` | Файл журналу сайту, наприклад `logs/web.log` (папка створюється автоматично) |
| `ADMIN_EMAIL` | Email адміністратора (для seed-скрипта) |
| `ADMIN_PASSWORD` | Пароль адміністратора, мінімум 8 символів (для seed-скрипта) |

Згенерувати `SESSION_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### Запуск

```bash
cd web
npm install
npm run seed
npm start
```

`npm run seed` створює адміністратора з `ADMIN_EMAIL` / `ADMIN_PASSWORD`. Якщо адмін уже є, скрипт оновлює його пароль на поточний `ADMIN_PASSWORD`. Тож після зміни пароля в `.env` достатньо ще раз запустити `npm run seed`.

Сайт буде доступний на `http://localhost:<PORT>`.

### Сторінки

| URL | Доступ | Що робить |
|---|---|---|
| `/` | усі | Огляд: картки «Курсів», «Всі напрямки» (гість) або «Ваші курси» (після входу), «Спільнота», «Ваш статус»; «Популярні курси» (перші 3 з каталогу) з посиланням «Усі курси →»; жовтий блок із кроками для перевірки сайту. Числа на картках поки що «—» |
| `/courses` | студент, адмін | Каталог усіх курсів сіткою карток. Гостя перенаправляє на `/register` |
| `/register` | усі | Реєстрація (email, ім'я, пароль); вимоги до полів позначаються галочками під час введення; посилання «Уже маєте акаунт? Увійти» |
| `/login` | усі | Вхід; посилання «Немає акаунта? Зареєструватися» |
| `/profile` | студент, адмін | Особистий кабінет: ім'я, email, роль, дата реєстрації, ID. Гостя перенаправляє на `/login` |
| `/admin` | лише адмін | Лічильники користувачів і таблиця всіх користувачів. Іншим — 403 |
| `POST /logout` | студент, адмін | Вихід (кнопка «Вийти» у верхньому правому куті) |

Інтерфейс: ліворуч бічна панель з навігацією (у гостя біля «Курси» і «Особистий кабінет» — замок), угорі праворуч перемикач теми, плашка статусу («Гість», «Студент» або «Адміністратор») і кнопки «Увійти» / «Реєстрація» (лише для гостя). На телефоні бічна панель стає шапкою, контент іде в одну колонку.

Тема: світла або темна. При першому відвідуванні береться з налаштувань системи, після натискання перемикача (сонце/місяць) вибір зберігається в браузері (`localStorage`). Кольори задані CSS-змінними, тому темна тема лише перевизначає їх у `:root[data-theme="dark"]`.

Каталог курсів («Курс Тест 1…9», напрямки Frontend / Backend / DevOps) — це тестові заглушки в коді (`web/src/courses.ts`), у базі даних курсів немає.

### Безпека

- Паролі зберігаються лише як хеш **bcrypt** (10 раундів).
- Сесія в cookie `sid` з `httpOnly` і `sameSite=lax`. Після входу ідентифікатор сесії генерується заново (захист від session fixation).
- Кожна POST-форма містить **CSRF-токен**; запит без правильного токена отримує 403.
- Серверна валідація: формат email, ім'я від 2 до 30 символів, пароль від 8 символів і не довший за 72 байти (обмеження bcrypt), унікальність email. Ті самі правила передаються у форму реєстрації для підказок у браузері (`web/public/register.js`), але остаточна перевірка завжди на сервері.
- Усі дані користувача виводяться в шаблонах через екранований тег EJS `<%= %>`.

### Обмеження (свідомо, для тестового завдання)

- Сесії зберігаються в стандартному `MemoryStore` express-session: після перезапуску сервера всі виходять з акаунтів. Для продакшну потрібне окреме сховище сесій (Redis, БД).
- Cookie без прапорця `secure`, бо сайт працює локально по HTTP. За HTTPS його слід увімкнути.

## 3. Unity-гра

### Відкриття проєкту

1. Unity Hub → **Add** → **Add project from disk** → папка `unity/`. Якщо версії 6000.6.2f1 немає, Hub запропонує її встановити.
2. Перше відкриття довше звичайного: Unity завантажує пакети й створює папку `Library/` (її немає в git).
3. Відкрийте сцену `Assets/Scenes/MainMenu` і натисніть Play.

### Керування

| Клавіша | Дія |
|---|---|
| W A S D | Рух (відносно камери) |
| Миша | Огляд камерою |
| Shift | Біг |
| Ctrl (утримувати) | Присідання |
| Space | Стрибок |
| F5 | Швидке збереження |
| Esc | Пауза |

### Що є в грі

- **Головне меню** «Тестік гейм» з кнопками «Грати» і «Вийти». За панеллю камера повільно облітає рівень.
- **Рівень**: сходи, ящики для стрибків (на 0,8 м можна застрибнути з землі, на 1,6 м — лише з нижнього ящика), тунель, який проходиться тільки присівши, і огорожа по периметру.
- **Персонаж** зібраний з low-poly деталей (шапка, шарф). Ходьба, біг, присідання й стрибок показані процедурною анімацією, під ногами м'яка тінь.
- **Меню паузи** (Esc): «Продовжити», «Завантажити збереження» (неактивна, поки збереження немає), «Головне меню», «Налаштування» (гучність і чутливість камери, зберігаються в PlayerPrefs). На паузі гра зупиняється (`Time.timeScale = 0`), курсор звільняється.
- **Збереження**: F5 записує позицію гравця в `save.json` у `%USERPROFILE%\AppData\LocalLow\DefaultCompany\Тестік гейм\`.
- **Стиль**: пастельна палітра з 5 кольорів, low-poly геометрія з плоским затіненням, градієнтне небо, туман і пост-обробка URP (Bloom, Vignette, Color Adjustments, Tonemapping).
- **Звук**: усі ефекти й фонова музика синтезовані кодом, зовнішніх аудіофайлів немає.

### Як усе створюється

Сцени, матеріали, меші, спрайти інтерфейсу й звуки не робилися вручну: їх генерують Editor-скрипти з меню **Tools**. Запускайте їх у такому порядку:

| Пункт меню | Що робить |
|---|---|
| Tools → Generate Audio | Синтезує звуки й музичну петлю в `Assets/Audio/*.wav` |
| Tools → Build Test Scene | Заново будує сцени `MainMenu` і `Game`, вміст `Assets/Art/Generated/` і список сцен у Build Settings. **Ручні зміни в сценах при цьому втрачаються** |
| Tools → Apply UI Font | Призначає шрифт з `Assets/Art/UiStyle.asset` усім текстам у сценах, не перебудовуючи їх |

Що де налаштовується:

| Що | Де |
|---|---|
| Шрифт, розміри й відступи інтерфейсу | `unity/Assets/Art/UiStyle.asset` |
| Кольори | `unity/Assets/Scripts/Visual/Palette.cs` |
| Рівні гучності | `unity/Assets/Scripts/Audio/SoundLevels.cs` |
| Швидкості, висота стрибка, висота присідання | компонент `PlayerController` на об'єкті `Player` у сцені `Game` |

**Свій шрифт:** покладіть TTF або OTF у `Assets/Fonts`, створіть із нього шрифт TextMeshPro через **Assets → Create → TextMeshPro → Font Asset** (такий шрифт динамічний, тож кирилиця з'явиться сама), вкажіть його в полі **Font** у `UiStyle.asset` і запустіть **Tools → Apply UI Font**.

Ті самі інструменти можна запускати без вікна редактора. Редактор з цим проєктом при цьому має бути закритий. Команди нижче для PowerShell, з кореня репозиторію. Шлях до `Unity.exe` залежить від того, куди Unity Hub встановив редактор. `Unity.exe` — віконна програма, тому PowerShell сам не чекає її завершення; `WaitForExit()` чекає, а потім друкується код виходу (0 означає успіх).

```powershell
$unity = "C:\Program Files\Unity\Hub\Editor\6000.6.2f1\Editor\Unity.exe"
$process = Start-Process $unity -PassThru -ArgumentList "-batchmode -quit -projectPath `"$PWD\unity`" -executeMethod TestSceneBuilder.Build -logFile `"$env:TEMP\unity-build.log`""
$process.WaitForExit(); "exit code: $($process.ExitCode)"
```

Методи для `-executeMethod`: `AudioGenerator.Generate`, `TestSceneBuilder.Build`, `UiFontApplier.Apply`. Журнал запуску — `%TEMP%\unity-build.log`; помилки компіляції шукайте в ньому за `error CS`.

### Збірка `.exe`

У редакторі: **File → Build Profiles → Windows → Build**. Або з кореня репозиторію при закритому редакторі:

```powershell
$unity = "C:\Program Files\Unity\Hub\Editor\6000.6.2f1\Editor\Unity.exe"
$process = Start-Process $unity -PassThru -ArgumentList "-batchmode -quit -projectPath `"$PWD\unity`" -buildWindows64Player `"$PWD\unity\Builds\Windows\TestikGame.exe`" -logFile `"$env:TEMP\unity-build.log`""
$process.WaitForExit(); "exit code: $($process.ExitCode)"
```

Папка `unity/Builds/` є в `.gitignore`. До збірки потрапляють усі сцени з Build Settings, зокрема `CollisionTest` (див. частину 4); з меню гри вона не відкривається. Гра за замовчуванням відкривається на весь екран. У вікні її можна запустити так: `TestikGame.exe -screen-fullscreen 0 -screen-width 1280 -screen-height 720`. Журнал гри з помилками й винятками лежить у `%USERPROFILE%\AppData\LocalLow\DefaultCompany\Тестік гейм\Player.log`.

## 4. Модель стільця

### Blender

Стілець повністю будує скрипт [`model/make_chair.py`](model/make_chair.py). Запуск із кореня репозиторію (якщо `blender` немає в PATH, вкажіть повний шлях, наприклад `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`):

```powershell
blender -b --python-exit-code 1 -P model/make_chair.py
```

`--python-exit-code 1` потрібен, щоб помилка в скрипті давала код виходу 1: без нього Blender завершується з кодом 0 навіть після винятку.

Що робить скрипт:

- починає з порожньої сцени, одиниці — метри;
- створює 6 окремих об'єктів: `Seat` (0,44 × 0,42 × 0,06 м, верх на висоті 0,45 м), `Back` (0,44 × 0,03 × 0,45 м, до висоти 0,90 м) і чотири ніжки `Leg_FrontLeft`, `Leg_FrontRight`, `Leg_BackLeft`, `Leg_BackRight` (0,04 × 0,04 × 0,39 м). Ліво й право — з погляду того, хто сидить на стільці;
- застосовує масштаб, поворот і позицію (Apply All Transforms). Через це origin кожної деталі — центр основи стільця на підлозі;
- додає Bevel (6 мм, 2 сегменти) і плоске затінення — low-poly вигляд, як у грі;
- створює два матеріали Principled BSDF: `Wood` (ніжки й спинка) і `Fabric` (сидіння). Кольори скрипт читає просто з `unity/Assets/Scripts/Visual/Palette.cs`: Wood — той самий відтінок, що в огорожі й деревах гри, Fabric — рожевий Rose;
- перевіряє розміри (висота 0,90 м, низ на z = 0) і зберігає `model/chair.blend` та `model/chair.fbx`.

Параметри експорту FBX і чому вони такі:

| Параметр | Значення | Навіщо |
|---|---|---|
| Forward / Up | `-Z` / `Y` | Переводить Z-up простір Blender у Y-up простір Unity |
| Apply Transform (`bake_space_transform`) | увімкнено | Поворот осей записується в саму геометрію, тож у Unity в об'єктів немає зайвого повороту −90° по X. Опція позначена експериментальною лише для арматур і анімацій, а тут статичні меші |
| Apply Scalings | `FBX All` | Unity імпортує 1 метр Blender як 1 метр зі scale 1, а не 100 |
| Apply Modifiers | увімкнено | Bevel потрапляє у FBX, а в `.blend` лишається модифікатором |
| Smoothing | `Face` | Грані лишаються пласкими |
| Object Types | лише Mesh | Без камер і світла |

### Unity

**Tools → Setup Chair Test** (або `-executeMethod ChairTestBuilder.Setup` у batchmode, команда як у частині 3) робить усе з нуля:

1. Копіює `model/chair.fbx` в `unity/Assets/Models/chair.fbx` і налаштовує імпорт: Scale Factor 1, Convert Units, без камер, світла, анімації й автоколайдерів.
2. Створює матеріали URP/Lit `Chair Wood` і `Chair Fabric` з кольорами палітри та підставляє їх замість матеріалів з FBX.
3. Перевіряє імпорт: у кожної деталі поворот (0, 0, 0) і масштаб 1, розмір стільця 0,44 × 0,90 × 0,42 м, низ на y = 0, стілець дивиться вздовж +Z. Якщо щось не так, скрипт зупиняється з помилкою.
4. Створює префаб `Assets/Models/Chair.prefab` з окремим BoxCollider на сидінні, спинці й кожній ніжці.
5. Створює сцену `Assets/Scenes/CollisionTest.unity`: підлога, стілець, 4 куби з Rigidbody над сидінням і персонаж із камерою. Персонаж — копія об'єкта `Player` зі сцени `Game` з тими самими компонентами (керування, анімація, звук кроків), без швидкого збереження, бо в тестовій сцені немає інтерфейсу. Сцена `Game` при цьому лише відкривається для читання й не зберігається.
6. Додає `CollisionTest` у Build Settings.

Сцени `MainMenu` і `Game` скрипт не змінює. Якщо перебудувати гру через **Tools → Build Test Scene**, згенеровані матеріали й меші персонажа створюються заново, тож після цього треба ще раз запустити **Tools → Setup Chair Test**.

У сцені `CollisionTest` керування як у грі (WASD, Shift, Ctrl, Space, миша). Курсор захоплюється для огляду; Esc звільняє або знову захоплює його.

### Why several BoxColliders instead of a MeshCollider

- **The shape is already boxes.** Every chair part is a box with a 6 mm bevel, so one BoxCollider per part matches it within millimetres. The bevel triangles add nothing useful to collisions.
- **Gaps stay open.** A convex MeshCollider would wrap the whole chair in one hull and turn the space under the seat and between the legs into a solid block. Separate boxes keep those gaps open: the character and the cubes collide with the real legs, seat and back.
- **Cheaper and more stable.** Box contacts are the simplest case for the physics engine: they are computed analytically and do not jitter. A non-convex MeshCollider tests contacts against every triangle and cannot be used on a moving (non-kinematic) Rigidbody, so the chair could never become a physics object.
- **Fast objects.** The falling cubes use `ContinuousDynamic` collision detection, so they do not pass through the 6 cm seat at high speed. Continuous detection is only supported for Rigidbodies with box, sphere or capsule colliders.

## Журнали (логи)

Бот і сайт пишуть окремі журнали: кожен рядок одночасно виводиться в консоль і дописується у файл з `LOG_PATH`.

| Проєкт | Файл (за замовчуванням з `.env.example`) | Що потрапляє |
|---|---|---|
| Бот | `bot/logs/bot.log` | запуск і зупинка, `/start`, переслані повідомлення клієнтів, доставлені відповіді оператора, натискання кнопок, блокування й розблокування, помилки |
| Сайт | `web/logs/web.log` | запуск, кожен запит (метод, URL, статус, час), реєстрація, вхід, невдалий вхід, вихід, відмови в доступі до `/admin`, відхилені CSRF-токени, помилки, seed |

Формат рядка: `2026-10-16T18:20:58.783Z INFO  User registered: user@test.local (id 2)`. Рівні: `INFO`, `WARN`, `ERROR`. Паролі в журнали не пишуться.

Переглядати журнал наживо (новий рядок з'являється одразу):

```powershell
Get-Content bot\logs\bot.log -Wait -Tail 50
```

```powershell
Get-Content web\logs\web.log -Wait -Tail 50
```

На Linux/macOS або в Git Bash: `tail -f bot/logs/bot.log` і `tail -f web/logs/web.log`.

Папки `logs/` у `.gitignore`.

## Перевірка

### Бот

Клієнт і оператор мають бути **різними акаунтами Telegram**: акаунт з `OPERATOR_ID` бот завжди вважає оператором.

1. `cd bot`, `npm install`, `npm start`. У консолі має з'явитися `Bot @<ім'я> started`.
2. **Оператор:** `/start`. Приходить інструкція оператора, внизу клавіатура «📊 Статистика», «👥 Останні клієнти», «🚫 Заблоковані».
3. **Клієнт:** `/start`. Приходить вітальне повідомлення «👋 Вітаю! Це тестовий бот підтримки…», внизу кнопка «/start». Натисніть її, і має прийти те саме повідомлення.
4. **Клієнт:** надішліть текст і фото. **Оператор** отримує обидва повідомлення пересланими, а під кожним службове «👤 Ім'я (@username), ID …» з кнопкою «🚫 Заблокувати».
5. **Оператор:** reply на переслане повідомлення текстом, потім фото. Клієнт отримує обидві відповіді.
6. **Оператор:** «📊 Статистика» показує кількість клієнтів, повідомлень усього й за сьогодні. «👥 Останні клієнти» показує список до 10 клієнтів з ім'ям, @username та ID.
7. **Оператор:** «🚫 Заблокувати» під повідомленням клієнта. Має спливти «Заблоковано: Ім'я».
8. **Клієнт:** напишіть щось. Клієнт отримує «Ви заблоковані…», а оператору нічого не приходить.
9. **Оператор:** «🚫 Заблоковані». Клієнт є у списку з кнопкою «✅ Розблокувати». Натисніть її, і повідомлення зміниться на «✅ Розблоковано: …». Тепер повідомлення клієнта знову доходять оператору.
10. Зупиніть бота (Ctrl+C) і запустіть знову. Reply оператора на старе переслане повідомлення все одно доходить клієнту. Усі ці дії видно в `bot/logs/bot.log`.

### Сайт

1. `cd web`, `cp .env.example .env` і заповніть значення, далі `npm install`, `npm run seed`, `npm start`.
2. Відкрийте `http://localhost:3000` (порт з `PORT`). Угорі праворуч статус «Гість» і кнопки «Увійти» / «Реєстрація».
3. **Реєстрація:** вводьте дані й дивіться на блок «Вимоги до даних»: біля кожної вимоги з'являється зелена ✓, коли поле заповнене правильно. Надішліть форму з помилкою, щоб побачити повідомлення сервера, потім з правильними даними. Вас перенаправить у кабінет.
4. **Кабінет** (`/profile`) показує ім'я, email, роль і дату реєстрації. Угорі праворуч статус «Студент» і кнопка «Вийти».
5. Відкрийте `http://localhost:3000/admin` студентом. Має бути сторінка **403**.
6. Натисніть «Вийти». Статус знову «Гість», а `/profile` перенаправляє на `/login`.
7. **Вхід:** з неправильним паролем має бути помилка «Невірний email або пароль», з правильним відкривається кабінет. Потім вийдіть.
8. Увійдіть як адмін з `ADMIN_EMAIL` / `ADMIN_PASSWORD` з `web/.env`. Статус «Адміністратор», у меню з'являється «Адмін-панель».
9. `/admin` показує таблицю всіх користувачів (ID, ім'я, email, роль, дата реєстрації). Усі запити, входи й відмови видно в `web/logs/web.log`.

### Гра

1. Відкрийте `unity/` в Unity Hub, сцену `Assets/Scenes/MainMenu`, натисніть Play. Панель «Тестік гейм» плавно з'являється, камера облітає рівень, грає тиха музика.
2. Наведіть курсор на кнопку: вона світлішає й тихо «тікає». Натисніть: вона темнішає, лунає м'який клік. «Грати» відкриває гру, внизу панель з підказками клавіш.
3. Ходьба (WASD) і біг (Shift): кінцівки рухаються в такт, при бігу персонаж нахиляється вперед, кроки чути разом із кроками ніг.
4. Стрибок (Space): на нижній ящик можна застрибнути з землі, на верхній — лише з нижнього. Чути стрибок і приземлення.
5. Сходи проходяться звичайною ходьбою. Тунель — лише з Ctrl. Якщо відпустити Ctrl під дахом, персонаж не встане, поки не вийде з тунелю.
6. Огорожа по краю арени не дає вийти за її межі.
7. F5: зверху з'являється «Збережено», лунає дзвіночок. Відійдіть в інше місце.
8. Esc: гра зупиняється, фон затемнюється, курсор видно. «Завантажити збереження» повертає персонажа на збережене місце й продовжує гру. Якщо видалити `save.json`, при наступній паузі ця кнопка неактивна.
9. «Налаштування»: повзунок гучності приглушує всю гру (на нулі тиша), повзунок чутливості змінює швидкість камери. Після перезапуску значення зберігаються.
10. «Головне меню» повертає в меню, «Вийти» зупиняє Play Mode (у зібраній грі закриває її). Музика звучить безперервно, стик 30-секундної петлі не чути.

### Стілець

1. Відкрийте `model/chair.blend` у Blender 5.2: 6 окремих об'єктів (`Seat`, `Back`, чотири `Leg_…`), на кожному модифікатор Bevel, матеріали `Wood` і `Fabric`. Origin усіх деталей — у центрі основи на підлозі.
2. За бажанням перезапустіть `blender -b --python-exit-code 1 -P model/make_chair.py`: у консолі з'являться розміри деталей, `chair bounds … z 0.000..0.900`, а `.blend` і `.fbx` перезапишуться.
3. У відкритому Unity виконайте **Tools → Setup Chair Test** (або `ChairTestBuilder.Setup` у batchmode, коли редактор закритий). У консолі для кожної деталі має бути `rotation (0.00, 0.00, 0.00) scale (1.00, 1.00, 1.00)` і `whole chair size (0.440, 0.900, 0.420)`.
4. Відкрийте префаб `Assets/Models/Chair.prefab`: на `Seat`, `Back` і кожній ніжці по одному BoxCollider, що збігається з деталлю.
5. Відкрийте `Assets/Scenes/CollisionTest` і натисніть Play. Чотири куби падають і лишаються на сидінні.
6. Підійдіть до стільця (WASD). Персонаж упирається в сидіння й ніжки й не проходить крізь них.
7. Esc звільняє курсор, ще один Esc знову захоплює його.
